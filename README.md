# Synera — Auto Chess Arena

基于 **Qt6 + C++17 + MinGW** 的单机 PVE 自走棋对战游戏。玩家购买英雄、布阵，与敌方自动战斗，逐关推进。

## 快速开始

### 依赖

- Qt 6.x
- CMake 3.16+
- MinGW 64-bit (或 MSVC 2022)

### 构建

```bash
mkdir build && cd build
cmake .. -G "MinGW Makefiles"
mingw32-make
```

或使用 Visual Studio：

```bash
mkdir build && cd build
cmake .. -G "Visual Studio 17 2022"
cmake --build .
```

## 操作方式

| 操作 | 说明 |
|------|------|
| 鼠标点击招募槽 | 购买英雄（金币足够时英雄出现在回收槽，该槽变空） |
| 鼠标点击 Refresh 按钮 | 花费 15 金币刷新全部 5 个招募槽 |
| 鼠标点击 Pop+ 按钮 | 购买人口上限（招募区下方） |
| 鼠标拖拽 | 从回收槽拖拽英雄到棋盘（玩家半场 y≥4） |
| 拖拽到英雄信息面板 | 将英雄卖回（返还基础价格） |
| 拖拽到回收槽 | 将英雄存入回收槽备用 |
| 拖拽同整星同名叠加 | 升星合成（按整星匹配，非精确星等） |
| 开始战斗按钮 | 点击右侧按钮开始本关战斗 |
| **F5** | 保存游戏进度（准备阶段） |
| **F9** | 读取游戏进度（准备阶段） |
| **R** | 完全重置游戏 |

## 游戏机制

### 英雄类型

| 类型 | HP | 攻击/治疗 | 射程 | 移速/攻速(帧) | 技能 |
|------|----|:---------:|:----:|:-------------:|------|
| 战士 Warrior | 100×(整星+1) | ATK 20×(整星+1) | 1 | 60/120 | 对最近敌方造成 80×(1+整星×0.5) 伤害 |
| 法师 Mage | 50×(整星+1) | ATK 10×(整星+1) | 4 | 60/120 | 周围 5×5 敌方全体燃烧 4 回合，每回合伤害 = 10 + 星数×5 |
| 辅助 Support | 80×(整星+1) | 治疗 20×(整星+1) | 2 | 60/120 | 全场 HP 最低 2 个单位各回复 30×(1+整星×0.5) |
| 刺客 Assassin | 15×(整星+1) | ATK 50×(整星+1) | 1 | 60/80 | 锁定距离≤2 的最近敌方造成 80×(1+整星×0.5) 伤害 |
| Boss | 500 | ATK 20 | 1 | 120/120 | 技能1: 全体英雄各 10 伤害（3法力）; 技能2: 米字路径全体英雄各 30 伤害（5法力） |

> 移速/攻速值为帧间隔（已全局翻倍以优化伤害显示），值越小行动越快。刺客攻速最快（80帧）。
> **整星** = starLevel，即英雄星等（0-3 星）。

### 升星机制

- 采用**整星制**：星等级 0-3 表示 0-3 颗完整星
- **3 个同名同星**英雄自动合成，结果为 `星等 + 1`（提高 1 颗星）
- 拖拽同名同星英雄叠加或在回收槽中满足 3 个相同英雄即可触发自动合成
- **属性加成整星生效**：属性公式使用 `整星 + 1`
- 刺客升星后初始法力值满格

### 技能系统

- 每次普攻/治疗积攒 **1 点法力值**，满蓝自动释放技能（需有有效目标）
- **无有效目标时不释放技能**，法力值保留至下回合
- 攻击技能（战士/法师/刺客/Boss）仅对敌方释放
- 辅助技能仅对友方释放
- 若有效目标数不足，则对现有有效目标使用；无有效目标则保留技能点

#### 技能目标验证

| 职业 | 有效目标条件 |
|------|------------|
| 战士 | 任意敌方存活 |
| 法师 | 技能范围内有敌方（5×5 以自身为中心） |
| 辅助 | 有受伤友方（HP < maxHP） |
| 刺客 | 曼哈顿距离 ≤ 2 内有敌方（由独立刺客系统处理） |

### 装备系统

英雄可装备最多 5 种类型的装备（每种 1 件），拖拽装备到英雄身上即可装备。

| 装备 | 类型 | 图标 | 效果 |
|------|:----:|:----:|------|
| Iron Sword | 攻击 | 剑 | 攻击力 +30 |
| Chain Mail | 防御 | 甲 | HP +150 |
| Speed Gloves | 攻速 | 攻速 | 攻速 ×0.8（帧间隔缩短 20%） |
| Blue Crystal | 法力 | 魔法石 | 技能消耗 ×0.5（减半） |
| Warhorse | 射程 | 战马 | 攻击范围 +1 |
| **Rune Greatsword** | 攻击 | 符文大剑 | 攻击力/治疗 +50，法力上限 -20 |
| **Swift Blade** | 攻击 | 极速战刀 | 攻击力 +30，攻速 ×0.5 |
| **Thorns Armor** | 防御 | 反伤铠甲 | HP +200，反弹 50% 所受伤害 |
| **Vitality Armor** | 防御 | 生命重甲 | HP +400，防御 +20（减伤），受治疗 ×1.5 |
| **Gale Gloves** | 攻速 | 疾风手套 | 攻速 ×0.7，法力上限 +20 |
| **Revive Stone** | 法力 | 复活石 | HP +100，法力回复 ×2，阵亡时消耗自身满血复活 |
| **Sniper Crossbow** | 射程 | 狙击弩 | 攻击力 +40，攻击范围 +2 |

> 高级装备（粗体）由基础装备合成获得，每次合成消耗 300 金币。

#### 装备获取与使用

- **掉落机制**：战斗中每击杀一个敌方有概率掉落装备（概率 = `关卡 × 10% + 5%`），无每关掉落上限
- **装备存储**：掉落装备显示在回收槽下方，最多保留 10 件
- **拖拽装备**：从掉落区拖拽装备到棋盘或回收槽中的英雄身上即可装备
- **卸下装备**：点击英雄身上的装备图标即可卸下到掉落区
- **升星保留**：合成时3个源单位的所有装备自动汇集到升级英雄身上（每种类型保留1件，多余的放回掉落区）
- 装备效果在 `equip()` 时立即生效（HP/ATK/攻速/射程/法力消耗等）

#### 装备合成

- 将基础装备拖拽到已装备兼容基础武器的英雄身上，消耗 **300 金币**自动合成高级装备
- 合成配方：

| 高级装备 | 合成材料 |
|---------|---------|
| 符文大剑 | 魔法石 + 剑 |
| 极速战刀 | 攻速 + 剑 |
| 反伤铠甲 | 甲 + 剑 |
| 生命重甲 | 甲 + 甲（第二个从掉落区拖入） |
| 疾风手套 | 攻速 + 魔法石 |
| 复活石 | 魔法石 + 甲 |
| 狙击弩 | 战马 + 剑 |

- 装备栏下方显示提示："每次升级装备需要耗费300金币"

#### 装备合成树窗口

- 点击左侧面板「装备合成树」按钮打开独立的合成参考窗口
- **非模态窗口**：不影响主窗口操作，可同时查看合成配方和进行游戏
- **独立渲染**：拥有自己的 `paintEvent`，与主窗口完全解耦
- **生命周期**：关闭窗口仅隐藏不销毁，下次点击按钮直接显示；程序退出时释放
- 窗口展示所有高级装备的合成配方、材料、效果和花费，按类型分色显示

### 战斗系统

- **帧级独立计时器**：每个单位有独立的 `m_moveTimer` 和 `m_attackTimer`
- 每帧计时器 +1，达到阈值时执行对应行动
- 移动计时器和攻击计时器完全独立，可同一帧同时触发
- 攻击范围内无目标时攻击计时器**每帧重置**，确保靠近后需等待完整攻速间隔

#### 战斗流程（每帧）

```
1. 清理过期特效
2. 收集棋盘存活单位
3. 燃烧结算（每 60 帧一次）
4. 刺客技能锁定处理（燃烧结算后立即执行）
5. 遍历所有单位：
   - 满蓝且非刺客 → 验证目标 → 释放技能或保留
   - 刺客 → 跳过主循环技能（由刺客系统处理）
   - 移动 & 普攻/治疗
6. 执行移动
7. 刷新伤害显示事件
8. 判定胜负
```

#### 燃烧 debuff

- 法师技能施加，每回合扣除 `10 + 星数 × 5` HP，持续 4 回合
- 燃烧伤害由施法者星数决定，0星=10/回合，3星=25/回合
- 独立于施法者生命周期
- 每 60 帧结算一次（燃烧间隔已翻倍）

### 羁绊系统

当场上满足特定条件时触发羁绊效果，在**每帧战斗开始时**自动判定（激活/失效）。

| 羁绊 | 条件 | 效果 |
|------|:----:|------|
| 战斗不息 | 3+ 战士 | 所有战士 HP 翻倍 |
| 吟咏魔典 | 2+ 法师 | 共享技能点（法师回蓝时平分给其他法师） |
| 生生不息 | 2+ 辅助 | 所有辅助治疗翻倍 + 治疗范围 +1 |
| 暗夜幻影 | 2+ 刺客 | 每个刺客生成 1 个分身（星数 = max(0, 本体星数 - 1)） |
| 全军出击 | 4 职各 ≥1 | 全体英雄 HP×1.5、ATK+20、技能消耗 -20 |

#### 羁绊触发规则

- **羁绊仅在有单位变化时重新判定**，避免每帧重复计算
- 羁绊激活时立即生效，失效时立即移除效果
- 准备阶段显示羁绊激活预判（仅预览，不实际生效）

#### 刺客分身机制

暗夜幻影羁绊激活时，每个刺客本体生成 1 个分身，特殊规则如下：

| 属性 | 规则 |
|------|------|
| **星数** | `max(0, 本体星等级 - 1)`，即比本体低 1 星，最低 0 星 |
| **初始法力** | 始终从 0 开始 |
| **本体死亡** | 分身不受影响，可继续战斗 |
| **关卡结束** | 所有分身自动消失（直接移除） |
| **人口计数** | 分身不影响场上角色总人数（不计入人口上限） |
| **羁绊享受** | 分身可享受全军出击等全体 buff |
| **羁绊触发** | 分身可参与全军出击等羁绊的条件判定 |

### 寻路索敌

- **索敌规则**：欧几里得距离最近优先，距离相等时优先横向距离更近的
- **移动规则**：优先前进（纵向靠近目标），其次左右（横向），避免双方错位时镜像循环卡死
- **辅助移动**：优先向右，其次纵向，最后向左
- 攻击性和辅助性角色使用相同索敌规则

### 刺客锁定机制

刺客技能**仅在燃烧结算帧处理**（每 60 帧一次），不通过主循环释放。

**锁定规则**：

1. 收集所有满蓝且范围内有敌方的刺客
2. 按棋盘顺序依次处理每位刺客：
   - 索敌（欧氏距离最近、横向破平，范围 ≤2）
   - **互杀检测**：若目标也是满蓝刺客 → 双方同归于尽，统计金币
   - **重复锁定**：若目标已被前序刺客击杀 → 自动重新索敌
   - 重索失败 → 本回合不释放技能，保留法力值
3. 对目标造成技能伤害并消耗法力值

### 伤害显示

- 每次攻击/治疗/技能产生 HP 变化后，在角色**右上角**显示浮动文本
- 格式：`+X`（绿色，治疗）或 `-X`（红色，伤害）
- 显示时长 = `max(最快攻速帧数 / 该单位本帧事件数 - 3, 0)` 帧
- 每帧结束后统一刷新，回合结束自动清空，不留残影

## 经济系统

### 金币获取

| 来源 | 金额 |
|------|------|
| 初始金币 | 1360 |
| 每关基础通关 | 100 |
| 击杀敌方 Warrior | 80 × (整星+1) |
| 击杀敌方 Mage | 60 × (整星+1) |
| 击杀敌方 Support | 30 × (整星+1) |
| 击杀敌方 Assassin | 30 × (整星+1) |
| 击杀 Boss | 200 × (整星+1) |
| 第 5 关前补助 | 800 |

- 玩家获胜：`m_gold += m_pendingGold + 100`
- 玩家失败（HP > 0）：`m_gold += m_pendingGold / 2 + 100`

### 金币利息

- 每关胜利后、添加战斗奖励前，**未使用金币变为 1.5 倍**
- 仅在**有下一关**时生效（即第 1-4 关胜利后）
- 失败或最终关不发放利息

### 英雄价格（波动制）

| 职业 | 基础价格 | 波动范围 |
|------|:----:|:----:|
| Warrior | 100 | 80 - 120 |
| Mage | 80 | 60 - 100 |
| Support | 50 | 30 - 70 |
| Assassin | 60 | 40 - 80 |

- 价格公式：`基础价格 + 5 × (rand()%5) × ((rand()%3) - 1)`
- 波动范围：基础价格 ±20（步长 5），最低 ≥ 1
- 价格在**每关准备阶段开始时**和**刷新招募区时**随机生成
- 招募区**实时显示当前波动价格**

## 人口上限

- 场上玩家方角色总数不能超过**人口上限**
- **初始人口上限**：4
- **升级费用**：`100 × (当前上限 - 4)` 金币（首次升级免费）
- **UI 显示**：棋盘右上角显示 `Pop: 当前人口/人口上限`
- **购买按钮**：左侧招募区下方「Pop+ $N」按钮
- 人口上限**跨关卡保留**（存档/读档支持）

## 招募系统

- 左侧面板分为**英雄信息区**（只读）和**招募区**（可交互）
- **英雄信息面板**（4 个）：显示每种英雄的基础属性（HP/ATK/Heal/射程/移速/攻速/价格），**拖拽英雄到对应面板可卖回**返还基础价格
- **招募区**（5 槽）：每槽随机显示英雄类型 + 波动价格，**点击直接购买**
- 购买后英雄**自动放入回收槽**空位（无空位则无法购买），该招募槽变空
- **刷新按钮**（Refresh $15）：花费 15 金币重随全部 5 个招募槽
- 招募区在每关准备阶段开始时自动刷新

## 关卡系统

| 关卡 | 敌方配置 | 总计 |
|:----:|---------|:----:|
| 1 | 每种类型各 1 个（0 星） | 4 |
| 2 | 每种类型各 2 个（0 星） | 8 |
| 3 | 每种类型各 3 个（0 星） | 12 |
| 4 | 每种类型各 2 个（2 星） | 8 |
| 5 | 每种类型各 1 个（3 星）+ Boss | 5 |

- 仅一方**全部阵亡**时战斗结束
- 玩家 HP 初始 100，失败扣除 `剩余敌人数 × 20`
- HP ≤ 0 → **GAME OVER**
- 通过全部 5 关 → **VICTORY**

## 回收系统

- 回收槽：**2 行 × 8 列 = 16 槽**（与棋盘宽度一致）
- **双重用途**：① 战后回收英雄暂存 ② **从招募区购买英雄的暂存空间**
- 购买英雄后自动放入空回收槽（无空位则无法购买）
- 关卡胜利后自动回收场上存活英雄（治疗 20 HP，保留技能点）
- **回收优先级**：星数高优先 → 同星按 战士 > 法师 > 辅助 > 刺客
- 回收槽满时，剩余英雄丢弃
- 准备阶段可从回收槽拖拽英雄到棋盘或放回
- 回收槽常驻显示（空槽半透明边框，有单位则实心色块）
- 支持回收槽内升星合成

## AI 使用说明

本项目在开发过程中充分利用 AI 辅助编程，但所有代码均经过人工审查与理解，确保对每一行代码拥有完全掌控。

### 项目规划

项目采用**渐进式迭代**的开发策略，将整体拆分为 9 个独立阶段（v0.5 - v0.13），每个阶段聚焦一个核心子系统：

1. **分层解耦**：将游戏拆分为渲染层（GUI）、逻辑层（战斗/经济/羁绊）、数据层（Board/Unit），各层通过明确接口交互
2. **逐模块交付**：每阶段向 AI 提供明确的功能规格（输入/输出/边界条件），由 AI 生成初始实现，人工审查后集成
3. **增量验证**：每完成一个阶段立即进行功能测试，确认无误后再进入下一阶段，避免错误累积
4. **重构预留**：在早期阶段（v0.5-v0.7）有意保留扩展点（如虚函数、枚举），便于后续阶段在不破坏现有代码的前提下添加新功能

AI 在以下环节提供了高效辅助：
- 模板代码生成（类声明、getter/setter、信号槽连接）
- 算法草稿（寻路启发式、排序比较器、状态机转换）
- UI 布局计算（坐标变换、几何绘制、颜色混合）
- 调试辅助（日志插桩、边界条件检查、内存泄漏排查）

### 核心代码解析

#### 1. 寻路与索敌系统

**运作原理**：每个单位在每帧战斗中独立决定移动方向，核心步骤如下：

1. **目标选择（索敌）**：遍历棋盘上所有敌对单位，计算欧几里得距离 `√((x₁-x₂)² + (y₁-y₂)²)`，选择距离最近的目标。若多个目标距离相等，优先选择横向距离（|dx|）更近的那个作为最终目标，避免在两个等距目标间反复切换。

2. **方向计算**：获得目标位置后，比较当前坐标与目标坐标：
   - 纵向偏移 |dy| > 0 时，优先纵向移动（攻击单位向目标靠近，辅助单位优先向右平移再纵向移动）
   - 纵向已对齐（|dy| = 0）时，再横向移动靠近目标
   - 这种"先纵后横"的设计避免了双方在同一行时出现镜像循环卡死的问题

3. **目标位置校验**：移动前检查目标格是否为空且合法（棋盘范围内）。若目标格被占用，尝试侧向绕行；若所有相邻格均被占用，本帧不移动。攻击范围内已有敌方时停止移动，直接进入攻击阶段。

4. **辅助单位特殊处理**：辅助英雄没有攻击目标，其"索敌"实际上是寻找 HP < maxHP 的受伤友方。移动方向上辅助单位优先向右探索，其次纵向，最后向左，确保辅助单位倾向于在战场中散布而非聚集。

#### 2. 每回合判定过程（含刺客技能判定）

**运作原理**：战斗的每一帧按以下严格顺序执行判定，确保各系统间的依赖关系正确：

1. **回合初始化**：清理上一帧的过期伤害特效（`m_hitEffects` / `m_slashEffects`），收集棋盘上所有存活单位到临时列表。若有单位在本帧之前死亡（HP ≤ 0），将其从棋盘移除并释放内存。

2. **羁绊判定**：仅在战场单位数量发生变化时（有单位死亡或新单位入场），重新统计各职业在场数量。依次检查 5 种羁绊的激活条件：
   - 若条件满足且该羁绊此前未激活 → 应用羁绊效果（HP翻倍/共享技能点/治疗翻倍/生成分身/全体buff）
   - 若条件不再满足且该羁绊此前已激活 → 移除羁绊效果（恢复原始属性）
   - 分身不计入人口统计但可参与羁绊条件判定

3. **燃烧结算**（每 60 帧一次）：遍历所有单位，对带有燃烧标记（`m_burning > 0`）的单位扣除 `10 + 施法者星数 × 5` 点 HP，燃烧剩余回合 -1。若单位因燃烧死亡，标记待清理。

4. **刺客技能判定**（燃烧结算后立即执行，每 60 帧一次）：
   - 收集所有满足条件的刺客：① 存活 ② 法力值满（`m_mana >= m_mana2`）③ 曼哈顿距离 ≤ 2 范围内存在敌方
   - 按棋盘位置顺序依次处理每位刺客：
     - 索敌选择距离 ≤ 2 内的最近敌方（欧氏距离优先，横向破平）
     - **互杀检测**：检查目标是否也是满蓝刺客。若是，双方立即同归于尽（HP 归零），赏金计入 `m_pendingGold`
     - **重复锁定检测**：检查目标是否已被本轮前序刺客击杀。若已被杀，自动重新索敌；若重索失败（范围内无敌方），本回合保留法力值不释放技能
   - 对通过所有检测的刺客，对目标造成 `80 × (1 + 整星 × 0.5)` 点技能伤害，消耗全部法力值

5. **主循环处理**（遍历所有存活单位）：
   - 非刺客单位满蓝时 → 验证技能有效目标（战士需任意敌方存活，法师需5×5范围内有敌方，辅助需有受伤友方）→ 有目标则释放技能，无目标则保留法力值
   - 刺客在燃烧帧由刺客系统处理，主循环中跳过其技能释放
   - 所有单位执行移动（向索敌目标靠近 1 格）和普攻/治疗（攻击范围内有目标时造成伤害或治疗）

6. **伤害显示刷新**：收集本帧所有 HP 变化事件，计算每个事件的显示时长（`max(最快攻速帧数 / 该单位本帧事件数 - 3, 0)`），在单位右上角绘制浮动文本。

7. **胜负判定**：检查双方存活单位数量。若玩家方全部阵亡 → 玩家失败；若敌方全部阵亡 → 玩家胜利。触发对应的关卡结束流程。

#### 3. 装备合成树窗口

**运作原理**：`EquipSynthWindow` 是一个完全独立于主窗口渲染管线的非模态子窗口，生命周期由主窗口 `Synera` 手动管理，核心设计要点如下：

1. **独立窗口创建**：构造时传入 `Qt::Window` 标志使其成为独立顶层窗口，设置 `WA_DeleteOnClose = false`（关闭不销毁）和 `WA_QuitOnClose = false`（关闭不退出程序）。窗口大小为 560×620 固定尺寸。

2. **关闭拦截**：重写 `closeEvent()`，调用 `event->ignore()` 阻止默认销毁行为，转而执行 `hide()` 隐藏窗口，并发射 `windowClosed()` 信号通知主窗口。主窗口按钮点击时若窗口已存在则仅调用 `show()`，实现"关闭即隐藏、点击即复现"的无反复创建模式。

3. **数据驱动渲染**：`initEntries()` 构建 7 条 `SynthEntry` 结构体列表，每条记录包含装备中文名、两种合成材料、效果描述、装备类型标签和类型对应颜色。7 种高级装备按类型分为：攻击装（符文大剑/极速战刀）、防御装（反伤铠甲/生命重甲）、攻速装（疾风手套）、蓝装（复活石）、射程装（狙击弩）。

4. **卡片式布局**：`paintEvent()` 中自定义 `QPainter` 绘制全套 UI：
   - 顶部标题 + 副标题 + 分割线
   - 基础装备图例行（5 种基础装备的图标与效果）
   - 合成卡片区：2 列网格布局，每张卡片由 `drawEntry()` 独立绘制，包含左侧类型色条、金色装备名、材料 `A + B` 公式、黄色 `→` 箭头、花费 300 金币标注、绿色效果描述

5. **完全自渲染**：窗口拥有独立的 `paintEvent`，不依赖主窗口的 `update()` 循环，与主战斗渲染完全解耦。主窗口仅负责在析构函数中 `delete m_equipSynthWindow` 释放内存。

#### 4. 独档存档机制

**运作原理**：存档系统使用 **JSON 格式** (`savegame.json`) 实现游戏状态的完整持久化，支持 F5 存档、F9 读档，核心流程如下：

1. **存档触发条件**：仅在 `GamePhase::Preparation`（准备阶段）且 `!m_gameOver` 时允许存档/读档，防止在战斗中保存不一致的中间状态。

2. **保存流程** (`saveGame`)：
   - 构建 `QJsonObject` 根节点，逐项序列化全局状态：`gold`、`currentLevel`、`playerHp`、`pendingGold`、`populationCap`
   - **招募区序列化**：遍历 5 个 `m_recruitSlots`，每槽保存 `type`（职业枚举值）、`price`（波动价格）、`empty`（是否空槽）
   - **棋盘英雄序列化**：遍历 8×8 棋盘，对每个存活的玩家英雄保存：位置 `(x,y)`、类型、星等 `star`、当前 `hp`、最大 `maxHp`、法力值、燃烧剩余回合、**5 槽装备**（按 `EquipType` 枚举顺序，用装备名称字符串标识，空槽存 null）
   - **回收槽序列化**：遍历 16 个回收槽，每槽保存槽位索引 `slot` + 同上完整英雄数据（类型/星等/HP/法力/燃烧/装备）
   - **装备掉落区序列化**：遍历 `m_equipDrops`，用装备名称字符串保存（空位存 null），含 `equipDropCount` 计数
   - 写入前先删除旧存档文件（`file.remove()`），确保覆盖而非追加

3. **读取流程** (`loadGame`)：
   - 打开 `savegame.json`，解析根 JSON 对象
   - 调用 `initGame()` **完全重置**当前游戏状态为初始值
   - 逐项恢复全局状态（金币/关卡/HP/人口等）
   - **英雄重建**：通过 `createHeroFromData` lambda 实现通用反序列化：
     1. 根据 `type` 和 `star` 调用 `createUnitFromPool` 创建单位（构造函数自动设定 `m_maxHp`）
     2. 重置法力值，**先恢复装备再设置 HP**（防御装 `equip()` 会触发 HP 加成，后续 `setHp()` 覆写为存档值，避免装备 HP 重复累加）
     3. 遍历装备名称数组，通过 `createWeaponByName` 按名称重建 Weapon 对象并调用 `equip()`
     4. 恢复法力值（逐个 `gainMana()`）、燃烧状态（`applyBurning(turns)`）
   - 恢复棋盘单位（`m_board.placeUnit`）、回收槽单位（含 slot 定位）、装备掉落区
   - 最后调用 `checkAutoStarUp()` 检查回收槽中是否有满足升星条件的英雄
   - 存档文件损坏或不存在时静默失败（`doc.isNull()` 直接 return）

4. **存档覆盖语义**：`F5` 随时可存，旧档被**先删后建**完全覆盖；`F9` 读档后游戏恢复至保存时的准备阶段状态，可重新布阵或直接开战。

#### 5. 拖曳幽灵渲染

**运作原理**：`renderDragGhost` 负责在拖拽过程中于鼠标光标位置绘制一个半透明的"幽灵"预览，让玩家直观看到正在拖动的单位或装备。该函数在 `paintEvent` 最末层（棋盘→回收槽→单位→信息面板→招募区→装备掉落区→**拖曳幽灵**→右侧UI→羁绊预览）调用，确保幽灵始终渲染在所有棋盘元素之上。

1. **单位拖曳幽灵**（`m_draggedUnit != nullptr`）：
   - 以 `m_dragCurrentPos`（鼠标实时位置）为中心，绘制 `CELL_SIZE × CELL_SIZE` 的圆角矩形
   - **透明度 0.75**：通过 `QPainter::setOpacity(0.75)` 实现半透明效果，使幽灵不会完全遮挡其下方的棋盘格和单位
   - 填充色由 `typeFillColor(type, isHero)` 决定，复用与棋盘单位相同的职业配色方案（战士橙/法师紫/辅助绿/刺客黄），敌方版本颜色更暗
   - 边框使用亮黄色（`QColor(255, 255, 100)`），宽度 2px，使幽灵在深色背景上始终醒目
   - 居中绘制单字中文职业标签（战/法/辅/刺），白色粗体 18px，由 `typeLabel()` 返回

2. **装备拖曳幽灵**（`m_draggedWeapon != nullptr`）：
   - 绘制 48×28 的紧凑圆角矩形（比单位幽灵小，匹配装备卡片的视觉比例）
   - **透明度 0.80**：比单位幽灵略不透明，因装备卡片面积更小且需突出文字可读性
   - 填充深紫灰色（`QColor(45, 40, 60)`），边框金色（`QColor(255, 210, 50)`），与掉落区装备卡片风格一致
   - 居中显示装备展示名称（如"符文大剑"），金色粗体 10px

3. **位置实时跟踪**：`m_dragCurrentPos` 在 `mouseMoveEvent` 中每帧更新为 `event->pos()`，并调用 `update()` 触发重绘。拖拽起始时（`mousePressEvent`）将该点初始化为鼠标按下位置，确保幽灵从拖拽第一帧就出现在正确位置，无跳变。

4. **save/restore 配对**：每次绘制前调用 `painter.save()` 保存画笔状态，绘制完成后 `painter.restore()` 恢复，确保半透明设置和颜色修改不影响后续渲染（右侧 UI、羁绊预览等）。

5. **两种幽灵互斥**：单位和装备不会同时被拖拽，但函数通过两个独立的 `if` 分支而非 `else if` 处理，逻辑上防御了同时非空的异常情况。

#### 6. 拖曳时棋盘格子高亮

**运作原理**：当玩家在准备阶段拖拽英雄时，`renderBoard` 实时检测鼠标下方玩家半场的每个空格子，将幽灵覆盖面积超过一半的格子高亮为绿色，提供直观的"可放置"视觉反馈。放置判定在 `mouseReleaseEvent` 中使用**完全相同的面积重叠算法**选择目标格，确保预览高亮与最终落点严格一致。

1. **触发条件**：三个条件同时满足才进入高亮判定：① `m_draggedUnit != nullptr`（有单位正被拖拽）② `m_phase == GamePhase::Preparation`（处于准备阶段）③ `m_board.isPlayerHalf(y)`（该行位于玩家半场 y≥4）。敌方半场和战斗阶段不触发高亮。

2. **幽灵矩形构造**：以 `m_dragCurrentPos`（鼠标实时坐标）为中心，构造 `CELL_SIZE × CELL_SIZE` 的虚拟矩形，与 `renderDragGhost` 中绘制幽灵的单位矩形尺寸完全一致，确保视觉幽灵与检测区域精确对齐。

3. **重叠面积计算**：对玩家半场的每个格子 `(x, y)`，计算其棋盘矩形 `cellRect(x, y)` 与幽灵矩形的交集：
   ```cpp
   QRect inter = cellRect.intersected(unitRect);
   int overlap = inter.width() * inter.height();  // 交集面积（像素²）
   ```
   高亮条件：`overlap > CELL_SIZE² / 2`（交集面积超过格子面积 50%）且该格未被占用（`!m_board.isOccupied(x, y)`）。满足条件时格子从默认暗蓝色填充切换为 `QColor(50, 90, 50)`（暗绿色）。

4. **放置时的一致性**：`mouseReleaseEvent` 中释放拖拽到棋盘时，遍历玩家半场所有格子执行**相同算法**——构造 `cellRect(x, y)` 与幽灵矩形求交集面积，选择 `overlap > unitArea / 2` 且 `overlap` 最大的格子作为落点。这保证了玩家看到的绿色高亮格子就是松手后英雄最终放置的位置，消除视觉与实际的不一致。

5. **格子填充色**：
   | 状态 | 颜色值 | 视觉效果 |
   |------|--------|---------|
   | 玩家半场（默认） | `QColor(40, 55, 80)` | 暗蓝色 |
   | 敌方半场（默认） | `QColor(75, 38, 38)` | 暗红色 |
   | 拖拽悬停高亮 | `QColor(50, 90, 50)` | 暗绿色 |
   | 格子边框 | `QColor(75, 75, 95)` | 灰蓝色，1px |

6. **装备拖曳不触发**：装备拖曳（`m_draggedWeapon`）不会触发棋盘格子高亮，因为装备只能拖放到英雄身上或掉落区，无需棋盘格级预览。
